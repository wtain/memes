# C4 Build Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An admin presses Build on a draft comics, picks which panels to keep, and gets one new active meme; unkept panels are flagged `comics_source`, pass their popularity to it and move to `comics-sources/<name>/` at the next move flagged run.

**Architecture:** One new column (`comics_panels.kept`, second migration); a build service that composes to a temporary file, registers the image, marks the comics built, flags and absorbs the unkept panels and releases the kept ones, all inside the request's transaction with a file-removal rollback action; `move_flagged` routing for `comics_source`; a guard against changing a `comics_source` flag; one endpoint; a Build dialog and built view in the frontend.

**Tech Stack:** FastAPI, async SQLAlchemy, Alembic, Pillow (via `batch/utils/comics_compose.py`), React 19 + TypeScript + vitest, JSON-schema type generation.

**Spec:** `docs/superpowers/specs/2026-11-02-multi-image-comics/2026-11-05-c4-build-design.md` (read it first; it holds the build steps, error mapping, move routing and UI behavior)

## Global Constraints

- Python 3.11 (`.venv311`; the worktree has none, use `H:\workspace_sandbox\memes\.venv311`). ORM models only in `Storage/models.py`. Repositories never `commit()`; the request transaction is owned by `get_async_db`.
- Router, then service, then repository. `backend_api.md` is updated in the task that adds the endpoint.
- Error body: `HTTPException(status, detail={"code": ..., **detail})`. Status map: `not_found` 404; `built`, `not_buildable`, `popularity_conflict`, `comics_source_flag` 409; `keep_invalid`, `compose_failed` 422.
- Positions shown to people and in error bodies are 1-based; stored and C2 positions are 0-based.
- Built file name `comics-<first 12 hex of sha256>.<ext>` in `BASE_PATH`; temporary name `.comics-build-<uuid4>.<ext>`; flag reason `comics_source`; popularity source `comics_build`.
- A popularity failure aborts the build (do not wrap `absorb` in `guarded`).
- The migration is never applied to a live environment in this plan; tests use the throwaway database `ocrdb_test` only. Never use `DATABASE_URL` of metal/general/it.
- Test commands: backend `cd Backend && pytest tests/<file>`; repository/integration `DATABASE_URL="postgresql+asyncpg://ocr:ocr@localhost:5432/ocrdb_test" pytest tests/integration/<file> -v` (never combine test roots in one `pytest` call); batch `pytest batch/tests/`; docs guard `pytest tests/docs/`; frontend `tsc -b`, `eslint src/ --max-warnings 0`, `vitest run` before every frontend commit.
- Commit messages end with the two attribution lines given in the session's system reminder.

## Review Focus

- Two admins pressing Build on one comics at once: exactly one built image and one set of absorption edges, the other gets `built` (Task 6).
- A panel file deleted or replaced between adding and building: named refusal with the 1-based position, no file left behind (Task 6).
- Commit fails after the file was written: the file is removed, a retry reuses the same file name; an existing image's file is never removed (Task 6).
- A comics source flag overwritten or cleared by another path (unflag, re-flag with another reason, batch clears): the move routing must not be lost (Task 3).
- Cyrillic comics name and a name differing only in case at move time: target folder exists, nothing overwritten (Task 4).
