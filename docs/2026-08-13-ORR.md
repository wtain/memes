# Operational Readiness Review — 2026-08-13

Scope: production readiness for a **public VPS deployment** — security, deployment pipeline,
runbooks/process, and the dev→prod data lifecycle (dev environments prepare/enrich data
offline; a curated subset needs to reach a production DB; not every table is assumed
necessary in prod; schema changes and data migration need a repeatable path; backups need a
real story).

Excludes `docs/superpowers/specs/`, `docs/superpowers/plans/`, and `docs/superpowers/reviews/`
per request — this review is based on `docs/security/admin-permissions-todo.md`, the rest of
`docs/` (`docs/adr/`, `docs/audit/`, `docs/process/`, `docs/runbooks/`, `docs/schema.md`),
root-level docs (`CLAUDE.md`, `CICD.md`, `SETUP.md`, `Readme.md`, `ARCHITECTURE.md`), CI
workflows (`.github/workflows/`), Dockerfiles/compose, and a spot-check of the current backend
code against the last full audit (`docs/audit/audit-2026-06-25.md`, ~7 weeks old).

**Task board used:** `board/todo/` — one markdown file per task, each linking to the matching
GitHub issue (also filed under the new `production-readiness` label, since that's the only
other tracker configured in this repo).

This document only records findings and opens tracking tasks — **design and implementation
decisions for each item are intentionally left for separate work**, as requested.

---

## What's already in place

Worth stating up front so the table below isn't read as "nothing works": the 2026-06-25 audit's
Tier 1 items (upload MIME/magic-byte validation, CORS `None` fix, rate limiting added, structured
logging, DB-aware health check) and most of Tier 2 (doc accuracy fixes, `docs/schema.md`, CI
trigger-path coverage, integration tests, `IMAGES_DIR` abstraction, generated-types CI check,
Dependabot) are done. CI is real and reasonably thorough: backend tests, coverage, Docker build +
Trivy scan, frontend lint/type-check/test, Android CI/release, integration tests against a real
Postgres+pgvector service container. The admin-permissions gap is already self-documented
(`docs/security/admin-permissions-todo.md`) rather than silently ignored, and the
`DATABASE_URL_READONLY` role for agent DB access is a genuinely implemented safeguard, not just
a plan.

The gaps below are what's left standing between that state and "safe to expose on a public VPS
serving real traffic."

## Documentation navigability concern

Flagging per the request to call this out explicitly: production-deployment information is
split across `CICD.md` (stops at "image pushed to registry"), `SETUP.md` (dev-workstation
setup, and its own Docker quick-start is broken), and `CLAUDE.md` (dev workflow only) — **no
single document describes how to actually run this in production.** That's really the same root
cause as issues #136/#141 above rather than a separate item, but worth naming as its own
readiness concern: until one of those lands, there is no canonical place to even start writing
a deployment doc without it going stale immediately.
